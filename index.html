proxy-rules

自用分流规则：一份自持数据，编译成 mihomo（Clash.Meta） 与 Xray 两种格式，定时构建并发布。

  • 站点：仓库
  • 构建状态
  • 产物分支
  • 最后构建：2026-10-10 22:16 UTC
分流模型：广告/追踪 → 拒绝 ｜ 自持强制代理 → 代理 ｜ 国内域名与 IP → 直连 ｜ 其余一切 → 代理（兜底）。

客户端仍按 tag 引多个 rule-provider（拦截 / 直连 / 代理是不同动作，必须分开）， 但地址只有一个前缀。本页由构建流程自动生成，与产物一起发布， 所以站点上的文件与订阅内容永远同一次构建、不会错位。

首次部署必须先放一次 dat：geodata 是「配置校验通过后才下载」， 不能做首次引导 —— 文件不存在时配置校验直接失败退出 （failed to open self-geosite.dat）。先执行： 
mkdir -p /usr/local/share/xray && cd /usr/local/share/xray
curl -fsSLO https://xinvxueyuan.github.io/proxy-rules/xray/self-geosite.dat
curl -fsSLO https://xinvxueyuan.github.io/proxy-rules/xray/self-geoip.dat
curl -fsSLo geosite.dat https://github.com/v2fly/domain-list-community/releases/latest/download/dlc.dat
curl -fsSLo geoip.dat   https://github.com/v2fly/geoip/releases/latest/download/geoip.dat
之后 geodata 的 cron 才会接管更新。
自建产物命名为 self-geosite.dat / self-geoip.dat， 避免与官方同名文件互相遮蔽（同名会让并写的 geosite:cn、 geoip:private 解析失败）。引用时用 ext:self-geosite.dat:<tag>。

校验与保证

每次构建都会：

  • 用真实内核加载产物 —— mihomo 启动后查 /providers/rules 的真实规则条数并与清单逐项对齐；Xray 用 run -test 加载 ext: 引用的 dat（并与官方 dat 同目录，验证不遮蔽）。
  • 做变异检验：故意删文件 / 写坏内容 / 清空规则集，校验必须报错， 否则说明校验本身是空壳。
  • 断言两种格式语义等价（同一份组装结果）。
